# StoryGalore V1 — Fully Functional Release Contract

## Product identity

**StoryGalore** is a creator-first entertainment platform for discovering, publishing, and monetizing stories across media. Books are the flagship publication type; V1 also supports images/galleries and creator posts. The domain model is media-agnostic so short/long video and audio can be enabled later without a schema rewrite.

> V1 is a working product, not a prototype or documentation-only scaffold. No user-facing flow may be represented by a dead button, fake success state, placeholder API, or TODO.

## V1 media scope

Enabled:
- Comic
- Series/episode
- Image
- Image gallery
- Creator post with text/image/comic references

Architecturally prepared but feature-flagged:
- Short video
- Long video
- Audio
- Mixed-media publications

Video transcoding/streaming infrastructure must not be required to launch V1.

Provider-specific approval/compliance is configuration, not an assumption. Do not enable a provider until its commercial/legal acceptance for the exact business model is confirmed.

Every payment webhook is idempotent, stored, normalized, reconciled, and connected to the internal ledger before entitlement state is trusted.

## Advertising V1

Free users may receive ads; paid ad-free entitlements do not. Adult content must never be monetized through an ad placement unless the selected ad provider explicitly permits that content/context.

Admin-managed inventory includes:
- home/discovery native slots
- series-page slots
- between-episode slots
- post-feed slots

The system supports campaigns, creatives, scheduling, targeting, frequency caps, budgets, provider health, impression/click events and daily aggregates.

## V1 acceptance tests

A release is V1 only when a clean environment can demonstrate:
1. Create account → verify/authenticate → edit profile.
2. Create creator profile → create series → upload comic → process pages → publish.
3. Guest discovers a published comic and can read an entitled free episode.
4. Reader progress survives refresh and a second device/session.
5. Comment → reply → moderation action works.
6. Free user sees an eligible ad slot; paid ad-free user does not.
7. Subscription payment event activates the correct entitlement.
8. Failed/duplicate/out-of-order payment webhooks do not corrupt subscription state.
9. Adult content is denied unless every required server-side eligibility condition passes.
10. Creator AI request checks entitlement/policy, supports `PLATFORM_CREDITS`, authorized `BYOK`, or `USER_HOSTED`, creates a job, and records billing mode, usage and provenance.
11. Admin can approve/hide content and see the audit event.
12. Admin dashboard displays real aggregated counters and charts from stored analytics events, not hard-coded demo data.
13. Admin can create/activate/deactivate an ad campaign and observe ad events in reporting.
14. Search returns published content according to permissions/rating rules.
15. Realtime updates work for at least comments, generation status, and relevant notifications.
16. All critical server-side mutations are authorized independently of frontend visibility.

## Definition of done

- `pnpm install` succeeds.
- Public and admin sites build successfully.
- Appwrite Go Functions compile and pass tests.
- CI runs lint/typecheck/test/build.
- No production route depends on mock data.
- No TODO/FIXME placeholders remain in V1 paths.
- Error, loading and empty states exist for every major screen.
- Accessibility and keyboard navigation are implemented for shared interactive components.
- Permission checks are tested server-side.
- Analytics events are idempotent where applicable.
- Secrets are never committed.
- Appwrite resources are created using official CLI/Console/Terraform workflows; no invented resource schema is committed.

## Post-V1

Short video, long video, audio, creator marketplace/payouts, advanced collaboration, richer recommendation models, and full video transcoding/streaming are post-V1 capabilities behind feature flags.

## Durable workflow orchestration

V1 includes a deterministic execution dispatcher. Cloudflare Workflows is the registered durable execution engine for DURABLE_JOB and DURABLE_WORKFLOW operations. Appwrite TablesDB remains authoritative operation state; Cloudflare Workflows is the only V1 durable executor.

Critical workflows must be idempotent, retry-safe, observable, and explicit about external side effects. Payment success remains provider-webhook/reconciliation driven rather than client-redirect driven.

## Appwrite MCP and durable workflows

Autonomous agents access Appwrite only through the Central Agent Gateway, its in-process Policy Engine, and the registered official Appwrite MCP connection. The unattended authentication model and exact tool catalog remain release blockers until verified. Cloudflare MCP is not part of the StoryGalore application runtime. Cloudflare Workflows remains the V1 durable workflow engine for registered long-running operations.


## Final V1 hardening

V1 includes an Operations Center, cross-system observability, disaster recovery/restore testing, MCP security, workflow operations, feature-flag management, complete content lifecycle handling, retention/deletion workflows, accounting-ready financial records, cost reservations/settlement, and release-gate testing. See `docs/V1_OPERATIONS.md`, `docs/OPERATIONS_CENTER.md`, `docs/SECURITY.md`, and `docs/TESTING.md`.

### Runtime configuration acceptance

V1 product/policy configuration MUST be hot-reloadable. Adult catalog/generation/discovery controls, BYOK/user-hosted AI switches, provider/model policies, feature flags and emergency kill switches must take effect without application restart or redeployment. See `docs/DYNAMIC_CONFIGURATION.md`.
