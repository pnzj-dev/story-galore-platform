# V18.6 — Internationalization, RTL and Language-Aware Media

## Status

V1 requirement. This is a cross-cutting platform capability, not a V1.5 feature.

Implementation (UI locale): Astro built-in i18n routing is enabled (default `en` unprefixed; `fr` and `ar` prefixed). Locale resolution and RTL direction follow `contracts/i18n/locale-resolution.yaml`; the canonical language catalog is `contracts/i18n/language-catalog.yaml`. UI strings live in `apps/web/src/i18n/messages/{en,fr,ar}.ts` (English is the key source of truth) and are resolved via `apps/web/src/i18n`. The chrome (header/footer/mobile nav, notification drawer, user menu) plus the home, auth, support, settings and error pages are translated with `fr`/`ar` route wrappers; studio and admin pages remain in the next batch. Content-language filtering is tracked separately (server-authoritative discovery).

## Non-negotiable invariants

1. UI locale is independent from preferred content languages.
2. Every language-bearing publication has a canonical primary language and a complete set of declared content languages.
3. Users can explicitly select `ONLY_SELECTED` content-language filtering.
4. Language filtering is server-authoritative and occurs before pagination, recommendation ranking, or cache acceptance.
5. `UNKNOWN` or missing publication language never matches `ONLY_SELECTED`.
6. Entitlement, age, jurisdiction, moderation, adult-content and publication-status policy checks remain independent and are never bypassed by language matching.
7. RTL is derived from the resolved UI locale and implemented with CSS logical properties; no hard-coded left/right layout assumptions.
8. Language identifiers are canonical BCP 47 tags, not translated labels.
9. Approved localizations are separate editions of the same canonical work and never overwrite the source edition.
10. AI translations retain provenance and require the configured review state before reader exposure.

## User experience

A user may have:

```yaml
uiLocale: fr-BE
contentLanguages: [fr, en, ja]
contentLanguageMode: ONLY_SELECTED
```

The UI is French, while media discovery returns only publications whose declared content languages intersect `fr`, `en`, or `ja`.

A user may instead use `ALL` to receive all eligible content while keeping a French UI.

## RTL

Initial RTL locales include Arabic, Hebrew, Persian and Urdu when enabled in the language catalog. The implementation must use logical CSS properties (`margin-inline`, `padding-inline`, `inset-inline`, `border-start-*`, etc.) and direction-aware component behavior.

## Discovery and search

Language is a first-class filter dimension in search, autocomplete, home, discovery, following feed, collections and recommendations. Search documents and recommendation projections must preserve language metadata. The filter must be applied before cursor pagination so page boundaries are deterministic.

## Reader

If a publication has multiple approved language editions, the reader may switch editions. Reading progress is keyed to the canonical publication/episode identity and must not be lost solely because the selected localization changes.

## Agents

Agents receive `uiLocale`, `contentLanguages`, and `contentLanguageMode` as scoped context where relevant. Agents must not infer language preferences from prompts when explicit preference data is available. External agents receive only the language context required for their task.
