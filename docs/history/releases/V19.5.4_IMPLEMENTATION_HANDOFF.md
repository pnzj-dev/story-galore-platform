# V19.5.4 Implementation Handoff

## This is a planning artifact only

Do not begin implementation from this file alone. The coding agent must resolve every task against the canonical registries and `contracts/implementation/execution-plan.yaml`.

## Authoritative order

1. `contracts/implementation/execution-plan.yaml`
2. `contracts/implementation/execution-task-index.yaml`
3. existing V19.5.4 registries and domain contracts
4. this document
5. prose documentation elsewhere

If these sources conflict, the higher item wins and the task is blocked until the lower artifact is regenerated.

## Agent startup procedure

1. Validate release/version.
2. Run strict YAML duplicate-key validation.
3. Run global determinism validation.
4. Run implementation-spec validation.
5. Load execution task index.
6. Select only tasks whose dependencies are `VERIFIED`.
7. Resolve every canonical contract reference.
8. Refuse the task if any required contract/resource/capability/test is missing.
9. Implement only the selected task.
10. Run its required tests.
11. Mark it `VERIFIED` only after all task gates pass.
12. Re-run impacted global validators.

## No implementation authorization

This handoff does not authorize:

- production deployment
- production migration
- provider activation
- commercial pricing activation
- tax policy activation
- real-money transactions
- real stablecoin payouts
- production agent execution

Those require the explicit approvals defined by the canonical contracts.


## V19.5.4 durable execution normalization

Cloudflare Workflows is the sole registered V1 durable workflow engine. The retired external workflow runtime is removed from the V1 architecture and must not reappear without a new explicit provider contract, capability-gap decision, migration plan and human approval. Retired payment-provider candidates are removed from the payment registry and documentation.
