# V19.5.26 — Book publication and gallery presentation model

## Decision

`BOOK` is the publication type for book-length works. `COMIC`, `MANGA`, `WEBTOON`, `STRIP`, and `GRAPHIC_NOVEL` are formats/content structures under BOOK, not publication type values. A comic page remains an `IMAGE` asset and its ordering/reading semantics belong to the BOOK format contract.

`IMAGE_GALLERY` is not a publication type. Gallery is a presentation mode over a collection of IMAGE assets. The collection entity/storage/content contract is not yet approved, so standalone publishable galleries remain blocked rather than being coerced into POST or MIXED.

The proposed canonical publication type union is `BOOK | POST | VIDEO | AUDIO | MIXED`. Media assets remain `IMAGE | VIDEO | AUDIO | DOCUMENT`.

## Migration gate

Existing `COMIC` publications must only be migrated to `BOOK` with format `COMIC` after data inventory and verification of all consumers. Existing `IMAGE_GALLERY` publications must be mapped to an approved collection model or individually reviewed; no automatic mapping to another type is permitted. Schema, API, lifecycle, authorization, analytics, UI, rollback, and explicit approval gates are required before production changes.

## Validation

The repository validator checks the proposed canonical type list, asset enum alignment, gallery presentation semantics, and migration blockers. Validation does not prove runtime migration or deployment.
