# V18.8 — Coding Agent Execution Specification

## Purpose

This layer converts StoryGalore's product and domain architecture into an executable implementation specification for autonomous coding agents.

## Source-of-truth hierarchy

1. `contracts/` — machine-readable behavior and invariants.
2. `docs/` — product intent, architecture rationale and human-readable requirements.
3. `AGENTS.md` — coding-agent operating rules.
4. Existing implementation — evidence only; it never overrides a canonical contract.
5. Agent inference — prohibited when a required contract is missing or ambiguous.

## Deterministic implementation rule

A coding agent MUST resolve every task to:

- one task contract
- one or more explicit requirement contracts
- one canonical implementation owner
- one or more concrete source paths
- persistence/API/provider mappings where applicable
- explicit authorization behavior
- explicit test mappings
- explicit Definition-of-Done gates

If any required mapping is absent or ambiguous, the agent MUST stop with `BLOCKED`.

## No-guessing rule

The agent may choose implementation details only where the contract declares the choice unconstrained. It may not infer business policy, permissions, financial behavior, provider pricing, resource identifiers, migration semantics, or deployment authority from nearby code.

## Bug-fix rule

Every bug fix MUST:

1. reproduce or establish a deterministic failing case;
2. identify the violated contract/invariant;
3. add a regression test;
4. implement the smallest contract-compliant fix;
5. run the full affected verification set;
6. produce provenance linking issue → task → branch → commits → tests → PR.

## Feature rule

Every feature MUST resolve product intent to contracts before implementation. A feature without a deterministic acceptance contract is not implementation-ready.

## Schema-change rule

Schema changes MUST use expand → migrate → contract. The agent must identify backup/restore and rollback implications before modifying a canonical persistence resource.

## Provider rule

Provider integrations are adapters. Model catalogs may be dynamic, but adapter behavior, normalized schemas, policy, authentication, cost source and credit eligibility must be explicit.

## Deployment rule

`DEPLOYMENT_CANDIDATE` is the normal terminal state for an autonomous coding task. Production deployment requires separate explicit authorization. An agent cannot grant itself that authorization.

## Evidence rule

A green status without recorded verification evidence is not a passing gate.
