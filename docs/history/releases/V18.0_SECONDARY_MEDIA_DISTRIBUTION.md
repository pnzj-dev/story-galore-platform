# V18.0 — Secondary Media Distribution

## Decision

StoryGalore uses Cloudflare as the PRIMARY media distributor and Bunny as the SECONDARY distributor. Appwrite Storage remains the canonical origin.

The term **SECONDARY** is normative. Do not use `backup` as a domain concept, API field, state, capability, or UI label.

## Runtime contract

```text
Request
  -> Authentication
  -> Age / jurisdiction / entitlement / moderation / creator policy
  -> Media authorization
  -> Distribution selector
       -> PRIMARY: Cloudflare
       -> SECONDARY: Bunny (only when enabled and eligible)
  -> Authorized delivery URL/token
```

Distributor adapters are transport/delivery infrastructure. They MUST NOT implement entitlement, age, moderation, subscription, creator ownership, or jurisdiction policy.

## Canonical origin

Appwrite Storage is the only canonical media origin. Neither Cloudflare nor Bunny becomes a source of truth. There is no public Appwrite fallback.

## Admin control

Authorized SRE_OPS or PLATFORM_ADMIN users can change `secondaryEnabled` through `media_distribution_config_update`. The mutation requires capability `operations.media_distribution.configure`, idempotency, expected revision, reason, audit, and the normal admin approval policy.

Effective modes:

- `PRIMARY_ONLY`: Cloudflare is the only eligible distributor.
- `AUTOMATIC_FAILOVER`: Cloudflare is preferred; Bunny may serve when Cloudflare is unavailable and Bunny is enabled/healthy.
- `SECONDARY_ONLY`: Bunny is explicitly selected for controlled operational use.

Invariant: when `secondaryEnabled=false`, effective behavior is `PRIMARY_ONLY`; the system MUST reject or normalize any attempt to activate SECONDARY.

## Failover

Failover is regional/request-scoped whenever health data permits. A circuit is `CLOSED`, `OPEN`, or `HALF_OPEN`. The selector must not globally switch all traffic because of a single regional failure.

Recovery requires successful probes before traffic returns to PRIMARY.

## Security invariants

1. Authorization precedes distributor selection for protected media.
2. A signed delivery token is bound to media asset, variant/path, audience/actor where applicable, policy decision, expiry, and distributor.
3. A token for Cloudflare is not automatically valid for Bunny unless the authorization service issues a Bunny-bound delivery authorization.
4. CDN caches cannot bypass authorization or poison public cache entries.
5. Adult restrictions remain enforced during SECONDARY delivery.
6. Deleted, quarantined, revoked, or unauthorized media remains unavailable through both distributors.
7. Distributor credentials are never stored in media distribution config, browser storage, MCP arguments, analytics, or Cloudflare Workflows history.

## Operational behavior

If PRIMARY is unavailable and SECONDARY is disabled/unavailable, the user receives a controlled degraded response. The system never exposes an origin URL as an emergency shortcut.

Runtime events are observational and do not create an alternate source of truth.

## Coding-agent implementation order

1. Implement contracts under `contracts/media/` and `contracts/state-machines/media-distribution.yaml`.
2. Implement `MediaDistributionService` with provider-neutral interfaces.
3. Implement `CloudflareDistributionAdapter` as PRIMARY.
4. Implement `BunnyDistributionAdapter` as SECONDARY.
5. Persist only configuration in `media_distribution_config`; health is an operational projection.
6. Route admin mutation through the media application service with admin capability authorization.
7. Add MCP/UI mappings from the compatibility registries.
8. Add health probes, circuit breaker, regional selection, recovery probing, and metrics.
9. Add deterministic unit/contract tests and failure-injection E2E scenarios.
10. Validate with `pnpm validate:media-distribution` and the existing cross-domain validators.

## Required failure scenarios

- PRIMARY unavailable + SECONDARY enabled -> authorized request uses SECONDARY.
- PRIMARY unavailable + SECONDARY disabled -> no distributor is selected; no origin URL fallback.
- PRIMARY regional failure -> only affected region may select SECONDARY.
- Unauthorized subscriber media -> denied even when SECONDARY is healthy.
- Adult media with adult policy disabled -> denied on both paths.
- Deleted media -> denied on both paths.
- PRIMARY recovery -> probe then return to PRIMARY.
- SECONDARY unavailable -> remain PRIMARY or degrade; never expose origin.
- Admin disables SECONDARY while active -> new requests stop selecting SECONDARY; in-flight delivery follows bounded token semantics without extending authorization.
- Admin re-enables SECONDARY -> eligibility returns only after health check.
