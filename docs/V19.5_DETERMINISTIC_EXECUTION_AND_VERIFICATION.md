# V19.5 — Deterministic Execution & Verification

## Purpose

V19.5 closes the implementation-specification gap across executable runtimes and adds a global fail-closed determinism gate.

## Absolute coding-agent rule

The coding agent MUST NOT infer missing architecture. If a requirement, mapping, provider contract, permission, schema, test, resource, or executable owner is missing or ambiguous, the agent MUST stop with `BLOCKED` and identify the missing contract.

## Canonical executable runtimes

- Astro applications on Appwrite Sites
- Appwrite Functions
- Cloudflare Agents
- Cloudflare Workflows
- Cloudflare Workflows Workers

Each executable has one canonical owner and must resolve to an input/output contract, capability, secret policy, resource map, failure policy, observability contract and test matrix.

## Appwrite Functions

All 27 Functions in `backend/appwrite/functions/function-catalog.json` now have registry entries, execution classes, schemas, resource/secret policies, idempotency rules, error catalog references and test matrices.

Functions remain stateless. Durable job state belongs to `operations`. Functions may not invent durable state or perform undeclared resource access.

## Global coverage

The global determinism gate validates the closure between executable runtimes, domains, commands, events, persistence, UI routes, authorization, providers, configuration, secrets, cache, tests, deployment and recovery.

## Passing the gate

A green determinism gate means the architecture is closed enough for implementation without architectural guessing. It does NOT mean the product has been implemented; implementation must still satisfy every contract and test.

Production remains separately gated by explicit human authorization.
